# Commit messages

Use [Conventional Commits 1.0.0](https://www.conventionalcommits.org/en/v1.0.0/): `<type>(<optional scope>): <summary>`

| Type | Use for |
|---|---|
| `feat` | a new feature |
| `fix` | a bug fix |
| `docs` | README, CHANGELOG, comments only |
| `refactor` | code change with no behavior change |
| `test` | adding or fixing tests |
| `chore` | tooling, config, dependencies |

Examples: `feat(board): add Past Due flag in days` · `fix(intake): handle files with no owner` · `docs: add architecture diagram`

Keep the summary under ~70 characters, imperative mood ("add", not "added"). Add a body for the *why* when it isn't obvious.
